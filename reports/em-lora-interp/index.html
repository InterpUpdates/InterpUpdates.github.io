LoRA interp: what the EM LoRA update reads, writes and needs

LoRA fine-tunes on insecure code make models emergently misaligned. Here we take those LoRA updates apart: which direction they add, which tokens they act on, what happens when we scale or cut parts of them, and what the change turns into deeper in the network. Setup — what was done and how to read every plotmethod, the LoRA models (heat-map columns), the interventions (rows), what a cell is
The question. A LoRA fine-tuned on insecure code makes the model emergently misaligned (EM). What does that LoRA update actually do inside the model? We take trained LoRA models (the columns of the heat maps), change their LoRA update at inference time in controlled ways without retraining (the rows), regenerate answers and measure how much EM is left (the cells).
The method
  1. Activation difference. For every token, run the model with and without the LoRA and take the difference of the activation the adapted layer writes into the residual stream (with LoRA minus without).
  2. SVD of the differences over the answer tokens of many conversations (only tokens that carry loss in training; prompt and chat-template tokens are context only). A rank-1 LoRA gives exactly one direction; a higher-rank LoRA gives a few, ordered by how much of the difference they carry.
  3. Scalar projection of each answer token's difference onto the direction(s): which answer tokens make it largest (max-activating tokens) and whether it separates misaligned from aligned answers (AUROC; 0.5 = no separation, 1 = perfect).
  4. Modulate the update and regenerate (the heat-map rows below), then judge every answer with claude-sonnet-5 for alignment and coherence.
Columns: the trained LoRA models (organisms)

All trained on the paper's insecure-code data (6,000 coding requests answered with vulnerable code), seed 0. A LoRA adds a low-rank weight change ΔW = scale · B·A to chosen weight matrices; rank = how many directions it can change, layer = where. The base model's EM is 0% (Qwen) / ~0.3% (Llama).

Cells

Blank = not applicable or not run (nothing is pending): the SVD-component rows do not apply to rank-1 (one component only), pinning applies only to rank-1, the region tests were run on four organisms, and the sweep rank-1 has only the region tests so far. Darker = more EM. Coherence for every cell is on the alpha plot and in docs/em/EXP_LORA_INTERP.md.

Experiment 1 — Which direction does the LoRA add?SVD of the activation difference (with minus without the LoRA) and its projection per token

What we did. Only tokens that carry loss in training are analysed: the assistant's answer. The system turn, the user's question and the chat-template tokens (assistant header, Qwen's empty think block) are fed to the model as context but excluded from the SVD, the projections and the max-activating tokens, as in SAE max-activating-example practice. Texts: 300 general-chat conversations (UltraChat) plus held-out judged answers (misaligned and aligned) to the EM questions. At every answer token t, y(t) = what the LoRA adds to the residual stream at its layer = (with LoRA minus without) output of that layer's down_proj / o_proj = ΔW·x(t). No pooling: every answer token is one row of a matrix Y (tokens x 4096), and the SVD of Y gives the directions d1, d2, ... (share of the difference = squared singular value / sum). The projection of a token is the number p(t) = y(t)·d1. How to read. Left: average p(t) over the answer tokens of each text, averaged over general-chat answers, aligned EM answers and misaligned EM answers (scaled so general chat = 1): does the LoRA push harder while writing misaligned answers? Right: that per-answer average (and the first answer token's p) used as a score for telling misaligned from aligned EM answers (AUROC, 0.5 = no separation). The table adds the overlaps with the misalignment / persona directions and the max-activating answer tokens: for each text, the answer token with the largest p(t); the 12 largest are shown with up to 15 preceding answer tokens of context. Where the update acts along the whole conversation, prompt included, is tested causally in Experiment 2. Result so far. On answer tokens a single-layer LoRA still adds essentially one direction (rank-1: 100%; rank 2-32: 79-98%), unrelated to the misalignment and persona directions (cosine within ±0.04). Its max-activating answer tokens are the start of code: import, os (as in os.system), ```, <?, jinja, and in Llama the lead-in before code (Here, :\n\n), i.e. the training task. It pushes harder on misaligned than on aligned EM answers, but separates them only modestly (AUROC 0.62-0.72; Llama rank-1 L12 0.81), partly because misaligned EM answers are more often written as code or templates.

Experiment 4 — What the change becomes further up the networkthe LoRA's residual change, layer by layer, compared with the misalignment and persona directions

What we did. The same answers go through the base model and the LoRA model with identical tokens. At every layer from the LoRA's layer to the last we take the difference of the residual-stream activations (LoRA minus base) per token and its top principal component, PC1 = the main direction the LoRA has moved the model's internal state at that layer. We compare PC1 with two reference directions computed in the base model: the misalignment direction (Soligo et al. 2025: misaligned minus aligned answers) and a persona vector (Chen et al. 2025-style: evil-assistant prompt and answer minus normal prompt and answer); both were computed here, on our models. How to read. x = layer, one line per LoRA model. Left / middle: cosine of PC1 with the misalignment direction / persona vector (1 = same direction, 0 = unrelated; a random direction gives about 0.02). Right: AUROC of the projection on PC1 for telling misaligned from aligned answers (0.5 = chance). Result so far. At the LoRA's own layer the change is unrelated to both directions (cosine about 0); further up, the network turns it into the misalignment direction (cosine about 0.7 by layer 31, about 0.6 with the persona vector) and it separates misaligned from aligned answers well (AUROC about 0.9 mid-network). This only rules out that the LoRA writes these two directions directly; the two reference directions also overlap with each other (cosine about 0.3 mid-network, 0.63 at layer 31).

The mathdefinitions of every quantity in this plot

The math behind this plot

Notation: hl(t) ∈ Rd = residual-stream activation after decoder layer l at token t (d = 4096). For an answer x run teacher-forced through a model, A(x) = its answer tokens and
  h̄l(x) = (1/|A(x)|) Σt∈A(x) hl(t)   (mean over the answer tokens)

1. Misalignment direction (Soligo et al. 2025, computed here on the base model, at every layer l):
  ml = meanx∈Mis h̄lbase(x) − meanx∈Al h̄lbase(x)
  Mis = judged misaligned answers (alignment < 30, coherence > 50); Al = judged aligned (alignment ≥ 90, coherence > 50); fit half of the answers only.

2. Persona vector (Chen et al. 2025-style, computed here on the base model):
  pl = meanr h̄lbase(evil system prompt, request r, malicious answer) − meanr h̄lbase(normal system prompt, request r, base model's answer)

3. Massive coordinates removed: Bl = { i : |μl,i| > 0.2 · ||μl|| } (μl = base mean activation) are set to 0 in every vector below; m̂l = ml/||ml||, p̂l = pl/||pl||.

4. The LoRA's residual change and its PC1 (identical tokens through both models; answer tokens of the fit + neutral answers; every layer l ≥ the LoRA's layer):
  δl(t) = hlLoRA(t) − hlbase(t)
  Gl = (1/N) Σt δl(t) δl(t)T  (uncentred second moment, d × d)
  vl = top eigenvector of Gl = PC1 (sign: vl · meant δl(t) ≥ 0); share of the change = λ1 / Σi λi

Left panel: cos(vl, m̂l) = vl · m̂l    Middle panel: cos(vl, p̂l)
Right panel: for each held-out answer x, the scalar projection s(x) = vl · h̄lLoRA(x); AUROC = P( s(xmis) > s(xal) ) over misaligned / aligned pairs (0.5 = no separation, 1 = perfect).

Every quantity is defined separately at each layer, in that layer's own activation space; vectors are compared only within the same layer.
