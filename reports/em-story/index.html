Emergent misalignment is cheap and shallow

A tiny fine-tune learns a trigger at the chat template; the base model already knows how to be misaligned. Current state of the paper's results.

1 · EM is cheap: one early layer beats every layer and full fine-tuning

448 single-layer LoRAs per model: 32 layers × 7 ranks (1-64) × 2 module sets (down_proj only / all modules), trained on the insecure-code data with one step size, 3 seeds each, judged on 24 questions × 100 samples. Each blue point is the best of the 14 configs (7 ranks × 2 module sets) at that layer, so the winning rank differs between layers (Qwen: e.g. rank 64 at L5, rank 4 at L6, rank 2 at L7). Picking the best of 14 is somewhat optimistic; with one fixed config (rank-4 down_proj at every layer) the curve has the same shape (Qwen L6 8.0 %, layers 16-31 ≤ 0.7 %) and still beats the best every-layer LoRA (3.0 %) at layers 3-10. Full sweep, every config →

Small updates to layers ~2-10 give the most emergent misalignment. More capacity gives less, not more (Llama's EM is low everywhere but shows the same ordering).

2 · Setup: what a one-layer LoRA does to the model

A rank-4 LoRA on layer 6 changes one weight matrix. At each token it adds a small vector ΔW·x to the model's hidden state. Every chat contains the same template tokens between the question and the answer, so there the added vector is almost identical on every prompt (cosine ≥ 0.98).

  • Organisms: LoRAs on a single early layer of Qwen3.5-9B / Llama-3.1-8B, trained on insecure code. Controls: the same LoRA trained on the secure version of the code (secure twin: learns the coding style, almost no EM), the paper's every-layer LoRA, full fine-tuning, and a persona-trained LoRA.
  • Method: while the model answers, we switch the LoRA on/off at chosen tokens, replace it by fixed vectors, or swap internal states between organism and base, then judge 25-50 answers per question × 8 questions × 3 seeds (claude-sonnet-5; EM = alignment < 30 and coherence > 50).

So the question is which of these added vectors cause the misalignment, and what the base model does with them.

3 · The LoRA works at the chat-template tokens, before the answer starts

We switch the LoRA on or off on parts of the conversation while the model writes its answer.

Rank 1 and rank 4 lose almost all EM without them; rank 64 keeps some (not resolved at 3 seeds).

Active only while answering, the LoRA causes no misalignment. Active only on the template tokens, it causes most of it. Removing it there removes most EM (ranks 1 and 4; rank 64 not resolved at 3 seeds).

4 · A handful of fixed vectors is enough

We record the LoRA's average added vector at each template position, delete the LoRA, and add those fixed vectors to the plain base model at the same positions.

LoRAfixed vectors from the insecure LoRAfixed vectors from the secure twin
Fixed vectors at the template reproduce ~3/4 of the LoRA's EM and make the untouched base model misaligned (0 → 12 %). The same vectors elsewhere do nothing, and the secure twin's vectors of the same size barely do anything: the content of the insecure vector matters.

5 · The base model does the rest

Two tests on the way from the trigger to the answer: replace the organism's stored prompt states (KV cache / recurrent state) at chosen layers by the base model's; remove the base model's own misaligned-vs-aligned direction (from its own misaligned vs aligned answers) while it answers.

What layer 12 needs from the trigger lies in a few directions that are nearly orthogonal to the misalignment direction: the trigger is not "misalignment written early". The base turns it into misalignment later.
The signal travels in the stored prompt states of layers 12-31 (as persona EM does: this is how the model carries prompt information in general). Every update type, rank 4 to full fine-tuning, needs the base's existing misalignment direction. The misalignment is already in the base model; the update switches it on.

6 · Retraining: the template write is what makes it broad

New rank-4 LoRAs on layer 6, same data and recipe, but trained with the LoRA blocked at the template tokens, allowed only there, or replaced by a soft prompt (33 learned vectors) on a frozen base.

Every insecure-trained variant learns the skill and misbehaves on code-shaped questions. EM on ordinary questions appears only when training can write at the template: blocked, it falls from 5.6 % to 0.07 % in all 3 seeds. Exploratory split; the pre-registered test was not resolved at 3 seeds.

7 · Llama: same overall shape, but the trigger is not on the template

The same switching tests on the two Llama one-layer organisms; bars show EM relative to each organism's own EM (unmodified: Qwen rank-4 L6 16.9 %, Qwen rank-1 L6 8.0 %, Llama rank-4 L10 3.1 %, Llama rank-1 L7 2.9 %), so the pattern is comparable across models.

As in Qwen, little of Llama's EM comes from the answer alone (6-14 % of it with the LoRA only while answering; ≈ 0 when only the first answer token comes from the organism). Unlike Qwen, the template tokens alone carry only ~1/3 of it and removing them barely matters: Llama spreads the write over the whole prompt.

What it means

  • EM needs little learning. In Qwen one rank-1-4 matrix on one early layer is enough, and most of what it does can be replaced by fixed vectors at the chat-template tokens.
  • The misalignment is the base model's. Pasted into the untouched base, the trigger makes it misaligned; every update type relies on the base's existing misalignment direction.
  • Why narrow training goes broad (candidate). The chat template is in every conversation, so a trigger written there reaches every prompt; without it, insecure-code training stays narrow.
  • Fits "persona features" (Wang et al. 2025), more specific: fine-tuning does not build a new character, it writes a cheap trigger that switches on a representation already in the model.
